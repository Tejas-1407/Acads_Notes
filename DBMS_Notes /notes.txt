Complete Concepts Learned (One Line Each)
Tables & SQL
Table → Stores actual records (rows).

Index → Stores search keys + pointers to rows.

Primary Key → Unique identifier of a row.

Foreign Key → References another table's primary key.

View → Virtual table created from a query.

Indexing
Primary Index → Index built on the storage/primary attribute.

Secondary Index → Index built on any non-storage attribute.

Clustered Index → Table order matches index order.

Unclustered Index → Index is sorted; table stays unchanged.

Dense Index → Every search key has an index entry.

Sparse Index → Only some keys/pages have index entries.

B+ Tree
Internal Nodes → Store only keys for navigation.

Leaf Nodes → Store keys + record pointers.

Leaf Linking → Enables fast range queries.

PUSH → Overflow sends key upward.

COPY → Leaf separator is copied to parent.

BORROW → Redistribute from sibling.

MERGE → Join two siblings.

PULL → Parent separator removed after merge.

Hash Index
Hash Index → Uses hash(key) to find bucket directly.

Bucket → Group of records sharing same hash result.

Equality Search → Best use case (=).

Range Query → Poor with hashing.

Static Hashing
Static Hashing → Fixed number of buckets.

Overflow Page → Extra page attached when bucket is full.

Extendible Hashing
Directory → Array of pointers to buckets.

Global Depth (GD) → Number of bits used by directory.

Local Depth (LD) → Bits needed to identify one bucket.

Split Image → Buddy bucket created during split.

GD = LD → Double directory, then split.

GD > LD → Split bucket only.

Delete → Merge with split image if possible.

How are keys organized? → B+ Tree (sorted) or Hash (buckets)

Does the table follow index order? → Clustered or Unclustered

30-second final revision (one line each)
Table = actual records stored on disk.

Index = shortcut that points to records.

Primary index = built on the table's ordering key.

Secondary index = built on a non-ordering attribute.

Clustered = data rows are physically ordered by the index key.

Unclustered = index is ordered, data is scattered.

Dense index = every search key has an index entry.

Sparse index = only some keys/pages have entries.

B+ Tree = balanced ordered index for equality + range queries.

Internal nodes = store keys and child pointers only.

Leaf nodes = store all keys + record pointers.

Split = overflow → divide node.

Copy = leaf split sends separator upward.

Push = internal split moves middle key upward.

Borrow = take one key from sibling during deletion.

Merge = combine siblings when borrowing isn't possible.

Hashing = key → bucket using a hash function.

Bucket = fixed-size page storing multiple records.

Collision = different keys map to the same bucket.

Overflow page = extra page chained to a full bucket.

Static hashing = fixed number of buckets.

Extendible hashing = directory grows using global & local depth.

Linear hashing = no directory; split buckets round-robin using Level & Next.

Hashing vs B+ Tree = equality → Hashing, range → B+ Tree.
